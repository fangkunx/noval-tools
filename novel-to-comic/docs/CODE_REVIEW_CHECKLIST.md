# 代码审查清单

> 基于《项目开发规范》的检查清单，所有 PR 必须通过以下检查。

---

## 🔍 代码审查清单

### 1. 命名规范
- [ ] 类名：UpperCamelCase，含义清晰
- [ ] 方法名：lowerCamelCase，动词开头
- [ ] 变量名：lowerCamelCase，语义明确
- [ ] 常量：UPPER_SNAKE_CASE
- [ ] 包名：全小写，无下划线

### 2. 架构规范
- [ ] Controller 层：仅处理 HTTP，无业务逻辑
- [ ] Service 层：核心业务，不依赖 Spring MVC
- [ ] 依赖注入：使用构造函数注入，非 `@Autowired` 字段
- [ ] 策略模式：新步骤实现 `StepStrategy` 接口

### 3. 编码规范
- [ ] 无 `System.out.println`，使用 `log.info/error`
- [ ] 异常处理：捕获具体异常，非 `Exception`
- [ ] 集合判空：使用 `isEmpty()`，非 `size() == 0`
- [ ] 并发安全：共享变量使用 `volatile` 或锁
- [ ] 工具类：私有构造函数，防止实例化

### 4. 数据库规范
- [ ] 表名：小写，下划线分隔，模块前缀
- [ ] 字段名：小写，下划线分隔
- [ ] 外键索引：已创建
- [ ] SQL：使用 `PreparedStatement`，无字符串拼接

### 5. API 规范
- [ ] URL：RESTful 风格，名词复数
- [ ] 响应格式：统一 JSON，包含 `success`/`error`
- [ ] HTTP 方法：GET/POST/PUT/DELETE 正确使用

### 6. 前端规范
- [ ] CSS：使用变量，无硬编码颜色/尺寸
- [ ] JS：使用 `const`/`let`，无 `var`
- [ ] 状态管理：统一使用 `State` 对象
- [ ] DOM 操作：优先使用 `textContent`，避免 XSS

### 7. 配置规范
- [ ] 配置项：lower-kebab-case
- [ ] 敏感信息：无明文 API Key 提交
- [ ] 环境配置：dev/prod 分离

### 8. Git 规范
- [ ] Commit 信息：`type(scope): subject` 格式
- [ ] 分支命名：`feature/xxx` 或 `fix/xxx`
- [ ] 无调试代码残留

### 9. 性能规范
- [ ] 批量操作：使用事务包裹
- [ ] HTTP 客户端：复用实例，非每次创建
- [ ] 集合：预估大小，避免频繁扩容

### 10. 安全规范
- [ ] 用户输入：校验和转义
- [ ] SQL：无注入风险
- [ ] API Key：未提交到 Git

---

## 🚫 严重问题（必须修复）

1. **SQL 注入风险**：字符串拼接 SQL
2. **敏感信息泄露**：API Key 明文提交
3. **异常吞没**：catch 后无处理
4. **线程安全问题**：共享变量未加锁
5. **XSS 风险**：用户输入直接渲染 HTML

---

## ⚠️ 警告问题（建议修复）

1. **命名不规范**：类名/方法名不符合约定
2. **日志缺失**：关键操作无日志记录
3. **魔法数字**：硬编码数字/字符串
4. **代码重复**：相同逻辑复制粘贴
5. **注释缺失**：复杂逻辑无注释

---

## ✅ 优秀实践（加分项）

1. **单元测试**：覆盖核心逻辑
2. **文档更新**：同步更新相关文档
3. **性能优化**：批量操作、缓存
4. **错误提示**：友好的用户提示
5. **代码复用**：提取公共方法/类
